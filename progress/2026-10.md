   → 要写 `v.x()` / `v.y()`。**一条 `C3861` 连带炸出 20+ 个候选重载，先修根因，影子错误自己消失。**

**2 个"编译抓不到"的坑**（只有自检输出能抓）：

- `operator+` 里 `return Vec2();` 占位没删 → 0 错 0 警，但 `a + b` 恒等于 `(0, 0)`（实测自检 ❌）
- `operator<<` 里 `","` 少一个空格 → 数字全对，输出 `(3,4)` 而不是 `(3, 4)`，自检照样 ❌（**格式就是一次字符串比较**）

**过程**：第一版 → 改完仍剩 3 个错（`x()` / `y()` 还是没加 `v.`）→ 第三版全对。

**规律**：**报错数量 ≠ 错误数量。** 4 个 error 只对应 2 个根因；一个根因会带出一串"看起来更吓人"的连带错误。
→ 先数根因，再动手，别一条条改。

**做对并值得记的**：`operator+=` 成员版返回 `Vec2&` 且 `return *this;`（链式赋值的前提）；`operator[]` **两个重载都写了**（非 const 返 `double&` 当左值、const 返 `const double&`）；`operator+` 没有返回引用（避开 `C4172`）。
