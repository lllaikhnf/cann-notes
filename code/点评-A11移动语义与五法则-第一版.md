## 一、唯一的错：声明的是 `tep`，用的是 `tmp`

第 105–106 行你写的是：

```cpp
    Buffer tep(4, 9);               // ❌ 名字叫 tep
    v.push_back(std::move(tmp));    // ❌ 这里却写 tmp
```

应该两边同名（同一份文件里，一个是 `tmp` 一个是 `tep` 就行）：

```cpp
    Buffer tmp(4, 9);
    v.push_back(std::move(tmp));
```

**为什么编译器只说"未声明的标识符"**：`C2065` 的意思是"这个名字我在当前作用域里没见过"。
编译器不会去猜"你是不是把 `tep` 写成了 `tmp`"，也不会提示"三行前有个很像的名字" —— 它只认识**名字完全一致**的标识符。

> `C2065` 有两种成因，它的报错文字对两者一视同仁：
> ① **真的没声明**（忘了 `int`、类型名打错）；
> ② **声明了但名字写岔**（这次的 `tep` / `tmp`，或者大小写、下划线差异）。
> → **看到 `C2065`，先回头看最近几行的变量名**，再去怀疑"是不是真没声明"。

**这一类错误的共同点**（A10 的 `void`、A9 的 `new int[]` 也算一族的）：**丢的都是"字母/关键字级别"的东西**，
不是逻辑。它们的特点是**编译器一抓就中**，代价只是编译一轮的时间 —— 反倒是那些能编过、结果却是错的（比如 A8 那个三元方向反了）才最贵。

## 三、做对的地方（这节含金量比 A10 还高）

| 位置 | 你写的 | 评价 |
| --- | --- | --- |
| TODO 1 移动构造 | 初始化列表 `:data_(other.data_), size_(other.size_)` + 函数体 `other.data_ = nullptr; other.size_ = 0;` | ✅ **偷 + 置空**两步都对，这是移动语义的核心 |
| TODO 2 移动赋值 | `if (this == &other) return *this;` → `delete[] data_;` → 偷 → 置空 → `return *this;` | ✅ **四步顺序完全正确**，自移动检查没漏 |
| TODO 2 签名 | `Buffer& operator=(Buffer&& other) noexcept` | ✅ 返回引用 + `noexcept`，一个字不多不少 |
| TODO 3 | `v.push_back(std::move(tmp));` | ✅ 知道具名左值不写 `std::move` 会走**拷贝**（白复制一次） |
| TODO 4 | `return Buffer(n, fill);` | ✅ 按值返回、直接构造 —— RVO 的机会留住了 |

**`noexcept` 两处都写了**，这点很多人第一次会漏：不写的话，`std::vector` 扩容时**不会**用你的移动构造，而是退回拷贝（因为标准库只敢在"移动一定不抛"时才用移动）。
