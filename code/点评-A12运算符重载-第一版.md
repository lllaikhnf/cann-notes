## 一、根因 1：`a += b;` —— 而 `a` 是 `const Vec2&`

你写的是：

```cpp
Vec2 operator+(const Vec2& a, const Vec2& b) {
    a += b;                    // ❌ a 是 const
    return Vec2();             // ❌ 占位实现没删（见第三节）
}
```

`C2678` 的附注其实已经把话说完了：

```
note: "Vec2 &Vec2::operator +=(const Vec2 &)": 不能将"this"指针从"const Vec2"转换为"Vec2 &"
note: 转换丢失限定符
```

`const Vec2& a` 的承诺是"我只是借来看，不改你"；而 `operator+=` 是**非 const 成员函数**（它要改自己的 `x_` / `y_`）。两件事冲突，编译器就不让你调。

修法就是惯用的三行 —— **先拷贝一份，副本随便改**：

```cpp
Vec2 r = a;                    // ① 先拷贝（a 是 const，动不了；副本是自己人）
r += b;                        // ② 复用你 TODO 1 写好的复合赋值
return r;                      // ③ 返回副本（值返回，不是引用）
```

> ★ 你的思路是对的：`operator+`（造新对象）用自由函数、`operator+=`（改自己）用成员函数，然后在 `+` 里复用 `+=` —— 这正是标准库的写法。只是漏了"副本"这一步。

## 二、根因 2：自由函数里没有 `this`

```cpp
std::ostream& operator<<(std::ostream& os, const Vec2& v) {
    os << '(' << x() << "," << y() << ')';   // ❌ 这里没有 x / y
    return os;
}
```

`operator<<` 是**自由函数**（不是成员函数），函数体里没有 `this`，也没有任何叫 `x` 或 `y` 的东西 → `C3861` 两条。要写参数名：`v.x()`、`v.y()`。

★ 这里有个值得记住的现象：

```
stu.cpp(95): error C3861: "x": 找不到标识符
stu.cpp(95): error C2593: "operator <<"不明确      ← 候选列了一屏（20 多个 ostream::operator<<）
```

**`C2593` 不是第二个错误**：`x()` 已经变成了 `<error type>`，`os << <error type>` 自然匹配不上任何重载，于是编译器把整个候选列表倒给你看（末尾那句 `尝试匹配参数列表"(basic_ostream<...>, <error type>)"时` 就是线索）。

> → 看报错的规则：**先看第一条，再顺着看它下面带 `note:` 的**。同一个表达式上的"不明确 / 无法匹配"，多半是前面那个错的影子 —— 别去数报错条数，去数**根因**。

## 三、坑 3（编译能过、结果错）：`return Vec2();` 占位没删

我把上面两处都改对、**唯独保留** `return Vec2();`，然后编译运行（**0 error 0 warning**）：

```
   t(1,1) += a(3,4) → t = (4, 5)      ← 期望 (4, 5)
   a + b = (0, 0)                  ← 期望 (4, 6)     ← 就是这里
   ...
自检：还有问题 ❌（对照上面每行的期望值）
```

`Vec2()` 是零向量，所以 `a + b` 恒等于 `(0, 0)`。数字全错的只有这一行，但自检只认全对。

**这一类"能编过、结果是错的"最贵**：编译器一句提示都不会给（A8 那次三元方向反了也是同一族）。编译错只是花你一轮编译时间，运行时错要花你调试时间 —— 所以**写完先别急着交，扫一眼有没有 `占位实现` 这几个字**。

