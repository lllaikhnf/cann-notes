# C++ 指针笔记 · 内存分区与三种"坏指针"

> 用途：双赛道计划 W1「指针与内存」核心笔记
> 结论一句话：**栈上的东西出了作用域就死；指针不能比它指向的对象活得久。**

## 一、内存分区

| 区域 | 装什么 | 生命周期 | 谁管 |
| --- | --- | --- | --- |
| **栈 stack** | 局部变量、函数参数 | **函数返回即销毁**（栈帧弹出） | 编译器/运行时自动 |
| **堆 heap** | `new` / `malloc` 出来的对象 | 手动 `delete` / `free` 才销毁 | **程序员** |
| 全局/静态区 | 全局变量、`static` 局部变量 | 程序运行期间一直活着 | 编译器 |
| 常量区 | 字符串字面量等 | 程序运行期间一直活着 | 只读 |

要点：`int x = 10;` 写在函数里 → 在**栈**上，函数一走，那块内存就"归还"了。

## 二、经典错误：返回局部变量的地址

```cpp
int* make() { int x = 10; return &x; }      // ❌ 悬垂指针
int main() { int* p = make(); std::cout << *p; }
```

**时间线**

1. `main` 调 `make()` → 分配栈帧，`x` 住这儿，写入 10
2. `return &x;` → 把地址交出去
3. `make` 返回 → 栈帧回收，**`x` 生命周期结束**，该地址变成"无主之地"
4. `*p` → 访问已失效内存 → **未定义行为（UB）**

**为什么"有时是对的"**：那块栈内存暂时没被覆盖，你就读到旧值 10。加一行 `printf`、换 `-O2`、换台机器，结果就可能变成垃圾值 —— 这就是 UB 的可怕。

```cpp
int* p = make();
std::cout << *p << "\n";                                   // 可能 10
int junk[100]; for (int i = 0; i < 100; ++i) junk[i] = i;   // 踩一遍栈
std::cout << *p << "\n";                                   // 大概率变垃圾
```

编译时加 `-Wall -Wextra`，编译器会直接警告：
`warning: address of local variable 'x' returned`

## 三、三种"坏指针"对比

| 名词 | 定义 | 触发场景 | 解引用后果 |
| --- | --- | --- | --- |
| **野指针** wild pointer | 从未初始化，指向随机地址 | `int* p; *p = 1;` | 随机崩溃/破坏内存 |
| **悬垂指针** dangling pointer | 曾经有效，所指对象已销毁 | 返回局部地址、`delete` 后继续用、`vector` 扩容后旧指针失效 | **静默读脏数据 / 破坏他人内存** |
| **空指针** nullptr | 明确"不指向任何对象" | `int* p = nullptr;` | 通常立即崩溃（可检测） |

**核心区别：空指针是"响的坏"，悬垂指针是"哑的坏"。**
- 空指针：崩溃位置明确，`if (p)` 能拦住
- 悬垂指针：`if (p)` 为真，读写出错要到很远的地方才爆，且现象随机

## 四、三问答案（自检）

**1. `x` 在哪个区、活到什么时候？**
栈；从定义处开始，到 `make()` 的作用域结束（`return` 那一刻）为止。注意区分：**作用域（编译器可见性）≠ 生命周期（运行时存在性）**，对 `static`/堆对象两者分离。

**2. 为什么违反的是生命周期规则，而不是语法规则？**
语法/类型完全合法（`&x` 是 `int*`，与返回类型匹配）→ 能通过编译，只给警告。指针只是"地址值"，不携带"所指对象是否有效"的信息，类型系统管不了 → 属于**运行时的语义错误（UB）**。现代 C++ 用 `unique_ptr` / `string` / `vector` 把生命周期写进类型里，才让编译器能替你挡。

**3. 为什么悬垂指针比空指针更危险？**
空指针明确无对象、通常立刻崩、可判空检测；悬垂指针地址仍在、可能读写成功 → 读到"看似合理"的垃圾（数据静默损坏），写入则破坏别的对象内存（堆破坏），且**常规判空手段无效**，出错位置远离现场。

## 五、正确写法（四种）

```cpp
// 1. 返回值（能用这个就别用指针）
int make_value() { return 10; }

// 2. 堆对象：谁 new 谁 delete，所有权要清楚
int* make_heap() { return new int(10); }        // 调用方负责 delete

// 3. static 局部：活到程序结束（能行，但非线程安全、语义怪）
int* make_static() { static int x = 10; return &x; }

// 4. 现代 C++：智能指针（W2 学 RAII 时正式用）
std::unique_ptr<int> make_smart() { return std::make_unique<int>(10); }

// 5. 出参 / 引用：让调用方提供存储
void make_out(int& out) { out = 10; }
```

## 六、空指针的正确姿势

```cpp
int* p = nullptr;             // C++11 起用 nullptr，别用 NULL / 0
if (p) *p = 1;                // 用前判空
delete p; p = nullptr;        // 释放后置空，防重复 delete（double free）
```

另一个高频坑：`std::vector<int> v; int* p = &v[0]; v.push_back(...);` → **扩容后 p 失效**（变悬垂）。

## 七、防身四招

1. `delete` 后立刻置 `nullptr`
2. 取了容器元素地址，就别再让它扩容
3. 要返回局部数据 → 改成"返回值 / 智能指针 / 出参"
4. 编译加 `-Wall -Wextra`，测试加 `-fsanitize=address`（ASan 能抓悬垂访问）

## 八、记住三句话

- 栈上的东西，**出了作用域就死**
- 指针**不能比所指对象活得久**
- 悬垂指针最可怕的地方：**它有时看起来是对的**

## 九、解引用 vs 指针算术：四个长得像的表达式

> 来源：2026-09-28 基础排查 A2 加练（设 `int a[3] = {10,20,30}; int* p = a;`）

| 写法 | 先做什么 | 结果 | 会改数组吗 |
| --- | --- | --- | --- |
| `*p + 1` | 先解引用取出 10，再 +1 | `11` | ❌ 不变（还是 10,20,30）|
| `*(p + 1)` | 先把指针移一格（地址 +4 字节），再解引用 | `20`（即 `a[1]`）| ❌ 只是读 |
| `*p += 1` | 解引用取出、加 1、**写回** | 数组变成 `11,20,30` | ✅ **唯一会改数组的** |
| `p + 1` | 只算地址，没有解引用 | 一个地址值（打印出来是 `0x...`）| ❌ |

**读代码口诀**：先看 `*` 贴着谁 —— `*(p+1)` 是"先算括号里的地址，再取内容"；`*p + 1` 是"先取内容，再加 1"。

⚠️ 必须记住：`std::cout << a;` 打印的是**数组首地址**，不是数组内容（C++ 的数组不会自动遍历）。

## 十、拷贝指针 ≠ 拷贝对象（浅拷贝为什么会炸）

> 来源：同一次排查里我错答的那题 —— 这是 A9「双重释放」的根，比扩容本身更重要。

```cpp
int  a = 5;
int  b = a;      // 拷贝"对象"：b 是另一个独立的 int → 改 b，a 不变（a 还是 5）
int* p = &a;
int* q = p;      // 拷贝"地址"：q 和 p 存同一个地址 → *q = 20 就是改 a（a 变 20）
```

一句话：**一个拷的是盒子里的东西，一个拷的是盒子的门牌号。**

亲眼验证（已跑过，看到三个地址一模一样就懂了）：

```cpp
int a = 5; int* p = &a; int* q = p;
std::cout << &a << ' ' << p << ' ' << q;   // 三个地址完全相同
*q = 20;
std::cout << a;                             // 20
```

**和动态数组的关系**（这就是类里必须自己写拷贝构造的原因）：

```cpp
IntArray a(3);
IntArray b = a;    // 默认拷贝构造 = 逐成员复制 = 只复制了 data_ 这个"门牌号"
// 于是 b.data_ == a.data_（同一块堆内存）
// 两个对象析构时各 delete[] 一次同一块内存 → double free → 崩
```

结论：**只要类里有 `delete[]`，就必须自己写拷贝构造（深拷贝）**。
只复制指针 = 两个对象共用一块内存 = 迟早双重释放。

## 十一、new / delete / delete[] 三兄弟

| 写法 | 申请了几个 int | 初值 | 正确释放 |
| --- | --- | --- | --- |
| `new int(7)` | **1 个** | **7**（括号里是初值）| `delete p;` |
| `new int[7]` | **7 个（一整块）** | **垃圾值** | `delete[] p;` |
| `new int[7]{}` | 7 个 | **全 0**（值初始化）| `delete[] p;` |

**规则：`new` 配 `delete`，`new[]` 配 `delete[]`，绝不能混。**

为什么必须配对：`new int[3]` 是**一次申请一整块**内存（不是申请 3 次），运行时记着"这是数组版、有 3 个元素"，
只有 `delete[]` 才知道怎么正确释放；对带析构函数的类型（如 `new std::string[3]`），
用 `delete` 只会析构**第一个**元素，其余两个的资源泄漏。

混用的后果（实测）：

```
ASan: alloc-dealloc-mismatch (operator new [] vs operator delete) → ABORTING
编译器警告：-Wmismatched-new-delete
```

⚠️ `new int[7]` 不写 `{}` 就是**垃圾值** —— `dynarray.h` 里 `new int[n]{}` 那个 `{}` 正是为了全 0。

### 实测（VS2022 cl 14.44，x64，debug CRT）

```
== 2) new int[7] 未初始化 ==
      值: -842150451 -842150451 -842150451 ...   ← 0xCDCDCDCD，debug 堆的"未初始化"填充值
== 3) new int[7]{} ==
      值: 0 0 0 0 0 0 0
== 4) new Tracer[3] + delete[]   配对正确 ✅
      构造 #1 #2 #3      析构 #3 #2 #1          ← 配平，干净
== 5) new Tracer[3] + delete     配错 ❌
      构造 #1 #2 #3      析构 #1                ← 只析构了 1 个
      然后进程直接崩掉（退出码 0xCFFFFFFF = 堆损坏）
```

### 为什么必须配对（机制）

`new T[n]` 的时候，运行时会在这块内存的**前面藏一个"元素个数"的小本子**（MSVC 是 8 字节 cookie），
返回给你的指针指向 cookie 的**后面**。

- `delete[]` 会**往回退 8 字节**读这个数 → 知道要析构 n 次 ✅
- 标量 `delete` 不认这个小本子 → 只析构**第一个**元素，还拿"cookie 后面"的地址去 free →
  地址对不上 → **堆损坏 → 崩** ❌

注意实验 5 的两层错：先"少析构 2 个"（资源泄漏），再"用错地址释放"（堆损坏崩溃）。
对 `int` 这种没有析构函数的类型，少析构看不出来，所以它经常**悄悄地错**——这才是最危险的地方。

### 铁证：反汇编里就能看到那个 cookie

`cl /FAs` 出来的汇编（/O2），两个函数一对比就明白了：

```
; void k(std::string *p) { delete[] p; }
        lea     rbx, QWORD PTR [rcx-8]   ; ← 往回退 8 字节，找到 cookie
        mov     r8,  QWORD PTR [rbx]     ;   读出元素个数 n
        call    ??_M@...                 ;   'eh vector destructor iterator'：析构 n 次
        ...
        call    ??_V@...                 ;   operator delete[]

; void h(std::string *p) { delete p; }
        mov     rbx, rcx                 ; ← 没有 -8！直接用你给的那个地址
        call    std::string::~basic_string   ;   只析构 1 次
        mov     edx, 32                  ;   sizeof(std::string)
        call    ??3@...                  ;   operator delete（地址是 cookie 后面那个 → 堆损坏）
```

**再强调一次：cookie 记的是"要析构几个元素"，不是"内存多大"。**
内存多大，分配器自己本来就记着，根本不需要 cookie 帮忙。

对 `int` 这种没有析构函数的类型：`new[]` 干脆**不加 cookie**（省那 8 字节），
于是 `delete p` 和 `delete[] p` 最终都是把同一个地址交给 CRT 去 free —— **什么都不会发生**。

实测：

```
A) new int[7]   + delete    -> 跑完了，不崩、不报错      ❌ 最危险的情况
B) new string[3] + delete   -> 当场崩（退出码 0xCFFFFFFF）❌ 只有 1 个析构跑过
```

所以配错到底炸不炸，取决于"**元素有没有析构函数**"，而不是"你写没写那个方括号" —— 这就是它阴的地方。



## 十二、数组核心（这块没吃透，动态数组一定写不下去）

### 1. 声明与初始化

```cpp
int a[5];              // 5 个 int，垃圾值
int a[5] = {1,2,3};    // 前 3 个是 1,2,3，其余自动补 0
int a[]  = {1,2,3};    // 长度自动推导为 3（最省事）
int a[5] = {};         // 全 0
```

### 2. 下标从 0 开始，合法范围是 0 .. n-1

```cpp
int a[3] = {10,20,30};   // a[0]=10 a[1]=20 a[2]=30，a[3] 越界
```

越界**不报错也不检查**，是 UB：可能没事、可能改掉旁边变量、可能崩。

### 3. sizeof 的两个用法

```cpp
int a[5];
sizeof(a)                 // 20：整个数组的字节数
sizeof(a) / sizeof(a[0])  // 5 ：元素个数（常用写法）
```

但**一旦传进函数就失效**（见第 4 条）。

### 4. 数组名会"退化"成指针（最容易踩）

```cpp
void f(int arr[]) { sizeof(arr); }   // 8（64 位）= 指针大小，不是数组大小！
f(a);   // 等价于 f(&a[0])；函数里 arr 的类型就是 int*
```

**结论：函数里永远拿不到数组长度，必须另外传一个 n。**
（这就是 `print(a, n)` / `grow(old, size, cap)` 里那个 `size` 的由来）

### 5. `a[i]` 就是 `*(a + i)`

```cpp
int a[3] = {10,20,30};
a[1] == *(a + 1) == 20
```

下标只是语法糖：先算 `a + i`（地址 + i×sizeof(元素)），再解引用。

### 6. ★ 数组不能整体拷贝/赋值（动态数组存在的理由）

```cpp
int x[3] = {1,2,3};
int y[3] = x;    // ❌ 编译错误：数组不能拷贝初始化
y = x;           // ❌ 编译错误：数组不能赋值
```

想要"拷贝一个数组"，只能自己写循环逐个搬 —— 这正是 `IntArray` 必须自己写拷贝构造的原因。
而"长度运行时决定 + 能自动增长"，就只能在堆上用 `new[]` 自己管（size / capacity）。

### 7. 静态数组的两个天生限制

- 长度必须在**编译期**确定（运行时才知道要几个 → 做不到）
- 存在**栈**上，空间有限（一般几十 KB ～ 几 MB，装不了大数组）

动态数组把数据放**堆**上、长度运行时决定 —— 这就是 `push_back` / 扩容要解决的问题。

### 8. 遍历三种写法

```cpp
for (int i = 0; i < n; ++i)      std::cout << a[i];   // 下标（最通用）
for (int* p = a; p < a + n; ++p) std::cout << *p;     // 指针（练指针算术）
for (int v : a)                  std::cout << v;      // 范围 for（只对"完整数组"和容器有效；对退化成指针的参数无效）
```

## 十三、printf 格式符与 size_t（`%zu` 到底是什么）

### 1. 拆开看

| 片段 | 含义 |
| --- | --- |
| `%` | 开始一个格式占位符 |
| `z` | **长度修饰符**：告诉 printf"这个参数的类型是 `size_t`"（C99 新增）|
| `u` | unsigned decimal：按无符号十进制打印 |

所以 `%zu` 读作"打印一个 `size_t`"。同理 `%zd` = 打印有符号版 `size_t`。

### 2. 为什么不能写死成 `%u` 或 `%d`

`sizeof` 的返回类型不是 `int`，是 **`size_t`** —— 一个"保证装得下任何对象大小"的无符号整型。
它的宽度**跟着平台变**：32 位程序里 4 字节，64 位程序里 8 字节。

而 `printf` 是**可变参数函数**：编译器不知道你后面塞了什么类型，它只看格式串去寄存器/栈里"按图纸取货"。
图纸（格式符）和实物（实参类型）必须严格配对，配错了不报错，是**未定义行为（UB）**。

```cpp
size_t n = sizeof(a);
printf("%zu\n", n);   // ✅ 正确
printf("%u\n",  n);   // ⚠️ 32 位碰巧对；64 位只取低 4 字节，大数值会打印错
printf("%d\n",  n);   // ❌ 拿有符号 int 的图纸去取 size_t 的货
```

⚠️ **最坑的地方：写错了常常"看起来是对的"**。本机实测（VS2022 cl 14.44，x64）：

```
a4-sizeof.cpp(21): warning C4477: "printf": 格式字符串"%d"需要类型"int"的参数，
                   但可变参数 1 拥有了类型"size_t"
                   note: 请考虑在格式字符串中使用"%zd"

right  %zu -> 20
wrong  %d  -> 20        ← 数值居然一样，所以特别容易蒙混过关
```

那句 warning 是唯一的救命绳 —— **警告不要无视**。换到 Linux 上、或者数值变大（超过 int 范围）时，就会打出垃圾数字。

### 3. 常用格式符对照

| 格式 | 对应类型 | 备注 |
| --- | --- | --- |
| `%zu` | `size_t` | `sizeof`、`strlen`、`vector::size()` 都用它 |
| `%zd` | 有符号 `size_t`（`ssize_t`）| `read()` / `write()` 的返回值 |
| `%llu` | `unsigned long long` | 固定 8 字节，跨平台安全 |
| `%lu` | `unsigned long` | ⚠️ Linux 64 位 = 8 字节，**Windows = 4 字节**，跨平台会翻车 |
| `%Iu` | `size_t` | MSVC 老写法，见第 5 条 |
| `%u` | `unsigned int` | 固定 4 字节 |
| `%d` | `int` | 有符号 |
| `%p` | 指针 | 打印地址用，别用 `%d` 打指针 |
| `%s` | 字符串（`char*`）| |
| `%f` / `%.2f` | `double` | 保留 2 位小数 |

### 4. 什么时候会碰到 `size_t`

- `sizeof(x)`
- `strlen(s)`、`std::string::size()` / `length()`、`std::vector::size()`
- `std::string::npos`（`find` 找不到时返回的值）
- 所以在这些地方 printf 都用 `%zu`

顺带一个结论：**`sizeof(a) / sizeof(a[0])` 的结果也是 `size_t`**，所以它也用 `%zu`：

```cpp
int a[5];
printf("元素个数 = %zu\n", sizeof(a) / sizeof(a[0]));   // 5
```

### 5. 不想记这些怎么办 + 兼容性

- **最省心的办法**：C++ 里直接用 `std::cout << sizeof(a);` —— 类型自动推导，永远不会错。
- 实在要用 printf：`printf("%llu\n", (unsigned long long)sizeof(a));` 也能保证跨平台。
- 兼容性：**VS2013 及以前不认 `%z`**，那时用 `%Iu`；VS2015 以后（包括现在的 VS2022）都支持 `%zu`。
  GCC / Clang 一直支持。

> 一句话记牢：**`sizeof` 和所有 `.size()` 的返回值都用 `%zu`，别用 `%d` / `%u`。**

## 十四、数组退化（decay）的来龙去脉

### 1. 它到底是什么

C/C++ 规定：**数组名出现在表达式里（少数例外除外），会被自动转换成"指向首元素的指针"**。这一步就叫 decay（退化）。

要点：`a` 这个符号的**类型**始终是 `int[5]`（所以 `sizeof(a)` 还是 20）；但你"取它的值 / 传参"时，能取到的只有首地址 —— 数组这个整体，语言不允许当值来搬运。

### 2. 两条规则，别混在一起

| 规则 | 内容 | 出现场合 |
| --- | --- | --- |
| ① 表达式 decay | 数组名在表达式里 → 首元素指针 | `f(a)`、`a + 1`、`p = a` |
| ② 形参类型调整 | `int arr[5]` / `int arr[]` 被**改写**成指针类型 | 函数声明里（C89 起的老规矩）|

② 就是"`int arr[5]` 里的 5 为什么不算数"的直接答案：**函数签名的类型里根本没有地方存 N**。`void f(int arr[5])` 的类型就是 `void f(int*)`，那个 5 收下就扔，编译器甚至不检查你实际传了几个元素。

### 3. 为什么语言要这么设计（三个理由）

1. **传参必须零成本**（最硬的理由）：如果数组能整体传参，`f(a)` 就要拷贝整块内存 —— 100 万个 int 就是 4 MB，函数还没干活先卡住。传指针只拷 8 字节，永远 O(1)。C/C++ 的哲学是"不为没用到的东西付钱"。
2. **历史包袱**：C 是从 B 语言长出来的。B 里**没有数组类型**，`a` 本身就是一个指针变量，`a[0]` 只是语法糖。C 想给数组分配真正的连续存储、想有独立的数组类型，但又要让 B 的老代码照样能编 → 保留了"数组名当指针用"的语义。
3. **下标机制建立在指针算术上**：`a[i]` 的定义就是 `*(a + i)`。既然下标是先算地址再解引用，那 `a` 就必须先变成指针，否则 `a + i` 无从谈起。

### 4. 实测：编译器其实"知道"长度

本机实测（VS2022 cl 14.44，x64）：

```
sizeof(a)                = 20   (a 的类型是 int[5])
sizeof(&a)               = 8
a       = 000000BD842FFAA8
a + 1   = 000000BD842FFAAC   向前走 4 字节   (跳 1 个 int)
&a + 1  = 000000BD842FFABC   向前走 20 字节  (跳整个数组!)
sizeof(r)  [引用接住]     = 20
count_of(a) [模板推导]    = 5
函数里 sizeof(arr)        = 8   (类型其实是 int*)
```

注意 `&a + 1` **跳了 20 字节** → 编译器完全知道 `a` 是 `int[5]`（否则不会跳一整块）。
所以 decay 不是"数组不存在了"，而是"**你没能把它当整体用**"：类型信息还在，只是拿不到手上。

### 5. 哪些场合**不**退化（实用清单）

| 写法 | 结果 |
| --- | --- |
| `sizeof(a)` | 20，保留数组类型 |
| `&a` | 类型是"指向 int[5] 的指针"，`&a + 1` 跳 20 字节 |
| `int (&r)[5] = a;` | **引用接住，不退化**，`sizeof(r)` = 20 ✅ |
| `decltype(a)` | `int[5]` |
| `for (int v : a)` | 有效（范围 for 内部直接按数组类型取 begin/end）|

### 6. ★ 为什么传参必须再传一个 n（信息守恒）

这是 A4 第二问的答案，分四层看：

**(1) 编译期层面**：函数只编译一次，却要服务任意长度的数组 —— `f(a5)` 和 `f(a100)` 调的是**同一份机器码**。参数区里只有 8 字节的地址，没有第二个 8 字节留给长度。

**(2) 运行时层面**：长度是"运行时才知道的数据"，而形参类型是编译期固定的 → 编译期存不了运行时的值。唯一办法：把长度也当成一个**参数**，在运行时一起送进去。

**(3) 信息守恒（核心）**：长度这个信息在 decay 的那一刻就**丢了**；想让函数知道，就得**另外再送一份**。
所以 `print(a, n)` / `grow(old, size, cap)` 里的那个 `size` 不是啰嗦，是补上丢掉的信息。

> 类比：快递单上只写门牌号，不写房间数。同一个门牌号可能是 5 间也可能是 500 间；
> 收件人想知道有几间，只能你另外告诉他。

⚠️ 代价：**传错 n 不报错**（越界就是 UB）。所以 n 必须由"真的知道长度的那个作用域"提供：`sizeof(a)/sizeof(a[0])`，或者容器自己的 `.size()`。

**(4) 反证**：一旦长度进了**类型**，函数就"知道"了 —— 但那要求长度是编译期常量（模板 N、`std::array`），或者像 `std::span` 那样**运行时把指针和长度打包成一个对象**（本质上还是送了一份长度，只是包起来一起走）。

### 7. C++ 的正规解法

```cpp
// ① 数组引用 + 模板：长度 N 被推导出来
template <typename T, size_t N>
size_t count_of(T (&arr)[N]) { return N; }      // count_of(a) == 5 ✅

// ② std::array：长度是类型的一部分，可以整体拷贝
std::array<int, 5> b = {1,2,3,4,5};
auto c = b;                                     // ✅ 真拷贝

// ③ std::span（C++20，现在最推荐）：指针 + 长度打包成一个参数
void print(std::span<int> s) {
    for (int v : s) std::cout << v;              // s.size() 永远正确
}
```

一句话：**这三种都是在把"丢掉的长度"重新塞回类型或参数里。**

### 8. A4 自测答案 + 常见错答

**题目**：`void f1(int arr[5])` / `f2(int arr[])` / `f3(int* arr)` 三种写法是否等价？函数里 `sizeof(arr)` 是多少？

**答案**：完全等价（形参都会被调整成 `int*`），函数里 `sizeof` = **8**（x64）；而 main 里的真数组是 **20**、元素个数 **5**。

**错答纠正**：

- ❌ "arr[5] 已经是个地址了" —— 不准确。在 main 里 `a` **不是**地址，它是一整块 5 个 int 的内存（`&a + 1` 跳 20 字节就是证据）。准确说法是：**形参类型被调整成了指针，函数收到的只是首地址**。
- ✅ "那个 5 是方便程序员看的" —— 对。

> 一句话记牢：decay 不是 bug，是"**数组不是一等公民 + 传参必须零成本 + 兼容 B 语言**"三件事合起来的必然结果；
> 代价是 —— **长度只活在类型里，一传参就没了，所以必须自己再传一个 n**。

## 十五、结构体 struct 与引用 &（从"一堆 int"到"一条记录"）

> 配套演示：`struct-demo.cpp`（双击 `build-struct-demo.cmd` 跑）
> 前置：第十二节（数组）、第十四节（decay）——**这一节正好解掉 decay 留下的那个坑。**

### 1. struct 解决什么问题

数组只能装**同一种**类型。可现实里"一个学生"是 `名字 + 分数 + 学号` 三样不同东西。
`struct` 就是**把若干个成员打包成一个新类型**：

```cpp
struct Student {
    char name[16];
    int  score;
    int  id;
};                       // ← 这个分号千万别忘（忘了他会在下一行报一堆莫名其妙的错）
```

用的时候当成一个普通类型：`Student a;`、`Student cls[3];`、`Student* p = &a;`。
成员用 `.` 访问：`a.score`；通过指针用 `->`：`p->score`。

### 2. struct 是"一等公民"，数组不是（接第十四节）

这是 decay 那节最实用的补救：

```cpp
int a[5] = {1,2,3,4,5};
int b[5] = a;            // ❌ 数组不能整体赋值/拷贝

struct Wrap { int v[5]; };
Wrap x = {{1,2,3,4,5}};
Wrap y = x;              // ✅ 可以！struct 会逐成员拷贝（数组在 struct 里被一并拷走）
```

一句话：**把数组塞进 struct，长度和内容就一起被搬走了** —— 这就是后面 `std::array` / `std::vector` 的雏形。

### 3. sizeof 与内存对齐：成员加起来 ≠ 结构体大小

```cpp
struct Bad  { char c; int i; char d; };   // sizeof = 12
struct Good { int i; char c; char d; };   // sizeof = 8     ← 同样的成员，只是换了顺序
```

规则（x64 MSVC）：每个成员要从**自己大小的整数倍**地址开始，整个结构体大小要能整除**最大成员**的大小。
- `char` 对齐 1、`int` 对齐 4、`double`/指针对齐 8
- `Bad`：`c`(1) + 补 3 + `i`(4) + `d`(1) + 补 3 = 12；`Good`：`i`(4) + `c`(1) + `d`(1) + 补 2 = 8

**为什么要有对齐**：CPU 读 4 字节数据时按 4 字节边界读最快，跨边界要读两次再拼。
**实用结论**：① 别用 `sizeof` 猜成员个数；② 想省内存就把**小的成员往后放**（或按从大到小排）。

### 4. 传参三兄弟（这一节最重要的对比）

| 写法 | 能不能改到原对象 | 要不要解引用 | 会不会拷贝 | 典型场景 |
| --- | --- | --- | --- | --- |
| `void f(Student s)` | ❌ 改的是副本 | 不用（像值） | **会拷一份** | 小结构体、真想要副本 |
| `void f(Student* p)` | ✅ 能 | 要（`p->x`） | 不拷 | 可能为空、要改指针本身 |
| `void f(Student& r)` | ✅ 能 | **不用**（`r.x`） | 不拷 | 要改原对象，首选 |
| `void f(const Student& r)` | ❌ 只读 | 不用 | 不拷 | **只读又不想拷贝 = 大赛标准写法** |

```cpp
void byValue(Student s)      { s.score += 100; }   // 外面没变
void byPointer(Student* p)   { p->score += 100; }  // 外面变了
void byReference(Student& r) { r.score += 100; }   // 外面变了，而且写法跟值一样
void byConstRef(const Student& r) { /* 只读，零拷贝 */ }
```

### 5. 引用 `&` 到底是什么

**引用 = 变量的别名**，不是新变量、不占新内存：

```cpp
int x = 5;
int& rx = x;      // rx 就是 x 的另一个名字
rx = 42;          // 等于 x = 42
&x == &rx         // 同一个地址（演示里打印出来一模一样）
```

三条硬规矩：
1. **定义时必须初始化**（`int& r;` 不合法）；
2. **一旦绑定就不能改绑**（`r = y` 是"给 r 指向的对象赋值"，不是"改成引用 y"）；
3. 引用**不能为空**（这正好补上指针的短板）。

> 和指针的关系：`T&` 可以理解成"**永远不为空、不用解引用、不能改绑的 `T* const`**"。
> C++ 里"要改原对象"的默认选择是**引用**；只有"可能为空 / 要改指向 / 要和 C 接口对接"时才用指针。

### 6. 常见坑

| 坑 | 现象 | 正解 |
| --- | --- | --- |
| `struct` 定义漏 `;` | 下一行报一堆莫名的错 | 补 `;` |
| 给 `char name[16]` 直接赋值 | `a.name = "小明";` ❌ 编译错 | 初始化时给，或用 `strcpy`，或改用 `std::string` |
| 传参传值却想改原对象 | 函数里改了、外面没变 | 用 `T&` 或 `T*` |
| 用 `sizeof(struct)/sizeof(成员)` 算个数 | 常有小数点、结果是错的 | 成员类型不同就别这么算；要数个数就另存一个 `n` |
| `p->x` 和 `*p.x` 混用 | `*p.x` 其实等于 `*(p.x)` ❌ | 记住优先级：`*p.x` ≠ `(*p).x`，所以才有 `->` |

## 十六、结构体数组排序（排序算法入门）

> 配套演示：`sort-demo.cpp`（双击 `build-sort-demo.cmd` 跑）
> 一句话：**排序 = 一条「比较规则」+ 一种「摆顺序的走法」**。结构体排序，难点永远在第一步。

### 1. 先定"按什么比"：多关键字比较

比赛里的排序十有八九是**多关键字**：先按主键，主键相等再比次键。

```cpp
// 规则：分数高的在前；分数相同，等级小的在前
bool better(const Player& a, const Player& b) {
    if (a.score != b.score) return a.score > b.score;   // 主键
    return a.level < b.level;                           // 次键
}
```

写成函数的好处：**选择排序、冒泡、`std::sort` 三种走法可以共用同一条规则**，改规则只改一处。
（`const Player&` 就是第十五节说的"只读 + 零拷贝"。）

### 2. 交换：引用第一次派上大用场

```cpp
void swapP(Player& a, Player& b) {   // 必须传引用，传值改不动外面
    Player t = a;                    // struct 能整体拷贝 → 交换只要三行
    a = b;
    b = t;
}
```
标准库也有 `std::swap(a, b)`，效果一样。

### 3. 选择排序：每轮挑出"最好的"换到前面

```cpp
for (int i = 0; i < n - 1; i++) {
    int best = i;
    for (int j = i + 1; j < n; j++)
        if (better(a[j], a[best])) best = j;   // 找这一轮第一名
    if (best != i) swapP(a[i], a[best]);       // 换到位置 i
}
```

- 比较次数**永远**是 `n(n-1)/2`（**不看数据长什么样**，n=6 就是 15 次）
- 交换次数 ≤ n-1（比冒泡少，这是它唯一的实战优势）
- 时间复杂度 **O(n²)**

### 4. 冒泡排序 + 提前退出

```cpp
for (int pass = 0; pass < n - 1; pass++) {
    bool swapped = false;
    for (int j = 0; j < n - 1 - pass; j++)
        if (better(a[j+1], a[j])) { swapP(a[j], a[j+1]); swapped = true; }
    if (!swapped) break;        // 这一轮一次都没换 → 已经有序，收工
}
```

**提前退出值多少钱**（演示里实测）：数据几乎有序时，选择排序照样 15 次，冒泡只要 **5** 次。
所以：**"基本有序"的数据用冒泡很划算；完全乱的数据两者都是 O(n²)。**

### 5. 比赛里真正该用的：`std::sort`

```cpp
#include <algorithm>
std::sort(a, a + n, better);      // 起始指针、结束指针、比较规则
```
- O(n log n)：n=1000 时约 10⁴ 次比较，手写选择排序是 5×10⁵；n=10⁵ 时手写是 **5×10⁹**（必然超时）
- `better` 是"函数指针"的一种用法，A8 会专门讲这个语法（lambda 也是同一件事）

> 手写排序不是白学：① 理解"比较/交换/有序不变式"；② 有些题要你按特殊规则排，或只需要"部分排序/求第 k 大"，那时手写反而直接。

### 6. 常见坑

| 坑 | 现象 | 正解 |
| --- | --- | --- |
| 交换函数传值 | `void swapP(Player a, Player b)` 调用后没变化 | 必须 `Player&` |
| 比较函数写反 | 想要降序却写成 `a.score < b.score` | 想清楚"我返回 true 表示谁排在前面" |
| 冒泡忘复位 `swapped` | 第一轮有交换，后面判断就永远为真，提前退出失效 | `swapped` 在**每轮开头**重新置 false |
| 字符串用 `==`/`<` 比 | `a.name == b.name` 比的是**地址**（数组退化成指针） | 用 `strcmp(a.name, b.name)`，或干脆用 `std::string` |
| 多关键字写一半 | 只比了 score，同分时顺序随机（不稳定） | 主键相等一定要接次键 |
| 排序后把原数组当没变 | `sort` 是**原地**改的（传进去的数组就是被改的那个） | 想保留原顺序就先 `memcpy` 一份 |

## 十七、中文乱码的「三层编码」（今天连着踩了三回，一次讲清）

> 触发场景：VS 里生成失败报 `C4819` / 控制台输出 `閽�鍜�` / 之前 `.cmd`、`.ps1` 也乱码 —— **全是同一件事：编码没对上。**

### 三层，每层都要"说好"

| 层 | 谁在决定 | 没对上的症状 | 怎么对 |
| --- | --- | --- | --- |
| ① **源文件编码** | 你把 .cpp 存成什么 | VS 报 `C4819`、字符串被读乱（`C3688 文本后缀无效`） | 存成 **UTF-8 带签名(BOM)**，或给编译器加 `/utf-8` |
| ② **编译器编码** | 编译时的 `/source-charset` | 同上（它按系统代码页 936 读了 UTF-8 的文件） | `cl /utf-8`（等号于同时指定源文件与执行字符集） |
| ③ **控制台编码** | 运行时的控制台代码页 | 程序跑通了、但中文显示成 `閽�鍜�` | 程序里 `SetConsoleOutputCP(CP_UTF8);` 或 `system("chcp 65001>nul");` |

### 你今天就是这么一步步踩过来的

1. **VS 生成失败**（第①②层）：源文件是 UTF-8 无 BOM，VS 按 GBK 读 → `鏈夐棶棰鉂` 这种乱码把字符串撕开 → 报错。
   我们的 `build-sort.cmd` 里有 `/utf-8`，所以命令行能编过、VS 编不过 —— **差别就在这个选项**。
2. **生成成功后，控制台还是乱码**（第③层）：程序按 UTF-8 输出，可控制台还是 936 → 显示成鬼画符。
   **修法（两行，放在 main 最前面）**：

```cpp
#include <cstdio>
#ifdef _WIN32
#include <windows.h>
#endif

int main(void) {
#ifdef _WIN32
    SetConsoleOutputCP(CP_UTF8);     // 让控制台按 UTF-8 显示
#endif
    printf("=== 手写选择排序后 ===\n");
    ...
```

或者更土但一样管用的写法（不用 `windows.h`）：

```cpp
#include <cstdlib>
system("chcp 65001 >nul");   // 把控制台切成 UTF-8
```

### 记忆口诀

> **文件存什么编码 → 编译器就得按什么编码读 → 输出时控制台也得按什么编码显示。三层任意一层错，中文就变鬼。**

看到这些信号，第一反应就是编码：
- `鏈夐棶棰`、`閽�鍜�`、`鍘熷` → UTF-8 字节被当成 GBK 解释了
- `C4819` → "这文件里有当前代码页表示不了的字符"

## 十八、函数指针 与 lambda（`std::sort` 第三个参数到底是什么）

> 上一节你写过 `std::sort(a, a + n, better);` —— 注意 `better` **后面没有括号**。
> 有括号是"调用它"，没括号是"把函数本身交出去"。这一节就讲清楚：函数怎么能当参数传。

### 1. 函数名 = 函数的地址

```cpp
bool byScore(const Player& a, const Player& b) { ... }

byScore;        // 不带括号 → 函数指针（地址）
byScore(x, y);  // 带括号   → 调用，得到 bool
&byScore;       // 取地址，和上面那个 byScore 是同一个东西
```

函数在内存里也有地址，函数名在**表达式**里会自动变成"指向该函数的指针"。所以函数可以像 int 一样被赋值、被传参。

### 2. 函数指针类型怎么写、怎么读

```cpp
bool (*cmp)(const Player&, const Player&);
//  ↑    ↑  └──────── 参数类型 ────────┘
//  │    └── 变量名（* 表示它是指针），整体是"指向函数的指针"
//  └── 该函数的返回类型
```

**读法：从名字往外读** —— "cmp 是一个指针，指向一个接收两个 `const Player&`、返回 `bool` 的函数"。

⚠️ **括号必须留着**，这两种写法完全不同：

| 写法 | 含义 |
| --- | --- |
| `bool (*cmp)(const Player&, const Player&)` | 指向函数的**指针**（我们要的） |
| `bool *cmp(const Player&, const Player&)` | 一个**函数**，返回 `bool*`（少了一对括号，意思全变了） |

嫌长可以起别名：

```cpp
using Cmp = bool (*)(const Player&, const Player&);   // 之后写 Cmp cmp 就行
typedef bool (*Cmp)(const Player&, const Player&);    // 老写法，等价
```

### 3. 用它做"可替换规则"的排序

```cpp
void sortBy(Player a[], int n, bool (*cmp)(const Player&, const Player&)) {
    for (int i = 0; i < n - 1; i++) {
        int best = i;
        for (int j = i + 1; j < n; j++)
            if (cmp(a[j], a[best])) best = j;    // 像普通函数那样调用它
        if (best != i) { Player t = a[i]; a[i] = a[best]; a[best] = t; }
    }
}
```

于是同一份排序代码，换规则只是换个名字：`sortBy(a, n, byScore);` / `sortBy(a, n, byLevel);`。

调用方式有两种写法，**完全等价**：

```cpp
cmp(x, y);      // 常用
(*cmp)(x, y);   // 先解引用再调用，也对（甚至可以写 (****cmp)(x,y)）
```

`sizeof(cmp)` 恒为 8（64 位），跟它指向的函数有多大没关系 —— **指针就是地址**。

### 4. lambda：规则"当场写"

每次比较规则都得起个函数名、还得放在文件别处，太啰嗦。lambda 让你把函数**就地**写出来：

```cpp
std::sort(a, a + n, [](const Player& p, const Player& q) {
    return p.score < q.score;        // 分数升序
});
```

语法拆解：

```
[捕获列表](参数列表) { 函数体 }
   ↑ 决定能不能用外面的变量
```

### 5. 捕获列表：lambda 怎么拿到外面的变量

| 写法 | 含义 |
| --- | --- |
| `[]` | 什么也不捕获，只能用参数和全局量 |
| `[limit]` | **值捕获**：拷贝一份 `limit`（之后的修改不影响它） |
| `[&limit]` | **引用捕获**：直接用外面那个变量 |
| `[=]` / `[&]` | 自动捕获所有用到的变量（值 / 引用）——方便，但容易埋坑 |
| `[desc, &n]` | 混着写也行 |

```cpp
bool desc = false;
std::sort(a, a + n, [desc](const Player& p, const Player& q) {
    return desc ? p.score > q.score : p.score < q.score;
});
```

**同一个 lambda，把外面的 `desc` 改成 true，规则就变了** —— lambda 一个字没改，变的是它捕获到的状态。

⚠️ **不写进 `[]` 就用不了**：

```cpp
int limit = 80;
std::sort(a, a + n, [](const Player& p, const Player& q) {
    return p.score >= limit;    // ❌ 编译错：limit 没有被捕获
});
```

这是设计，不是 bug：编译器不许你偷偷依赖外部变量，要用就明写出来。

### 6. lambda 的类型：写不出来，所以用 auto

每个 lambda 都有一个**编译器现场生成的、独一无二的类型**，你拼不出它的名字：

```cpp
auto twice = [](int v) { return v * 2; };   // ✅ 用 auto 接住
printf("%d\n", twice(21));

std::function<bool(const Player&, const Player&)> f =
    [](const Player& p, const Player& q) { return p.score < q.score; };  // ✅ 类型擦除版
```

区别：`auto` 接住的是**真实类型**（零开销，但只能存这一个 lambda）；`std::function` 什么兼容的都能装（能存进容器、能当成员），代价是一次间接调用。**能用 auto / 模板就用，需要"存起来"才用 `std::function`。**

### 7. 比较规则的硬要求（A7 那个 `C3889` 的根因）

`std::sort` 第三个参数必须是 **bool 返回、能构成"严格弱序"** 的规则，而且**不能修改元素**（所以参数用 `const Player&`）：

- 返回 `bool`——返回 int、返回 void 都不行
- `cmp(a, a)` 必须为 `false`（自己不能小于自己）
- 规则必须能排出先后；**规则"区分不出元素"时，排序看起来没生效**：

```cpp
// 六个人的名字都是 2 个汉字 = 6 字节，strlen 永远相等
std::sort(a, a + n, [](const Player& p, const Player& q) {
    return strlen(p.name) < strlen(q.name);   // 排完顺序没变
});
```

这不是 `std::sort` 坏了，是规则没有区分度。写规则前先问自己一句：**这条规则能把这些元素排出先后吗？**

### 8. 别踩清单

| 坑 | 后果 | 正确写法 |
| --- | --- | --- |
| `std::sort(a, a+n, better())` | 传进去的是调用结果 | 去掉括号：`better` |
| 函数指针类型丢了括号 `bool *cmp(...)` | 变成"返回指针的函数" | `bool (*cmp)(...)` |
| lambda 用外部变量却没写 `[]` | 编译错 | 写进捕获列表 |
| 规则里改元素（参数没 `const&`） | 结果不可预测 | `const Player&` |
| 规则永远返回 `false` | 顺序不变（像没排序） | 检查规则是否有区分度 |
| 用 `[&]` 捕获局部变量后 lambda 活得更久 | 悬空引用 | 需要留存就用值捕获 / `std::function` |

### 记忆口诀

> **函数名不带括号 = 函数的地址；带上括号 = 调用它。**
> **`bool (*cmp)(... )` 那对括号不能丢。**
> **lambda = 无名函数 + 捕获列表；要用外面的变量，就得写进 `[]`。**

## 十九、类与对象：构造 / 析构 / RAII（把 `grow` 收进一个类）

> 前面练的 `grow` 是"三个散着的变量 + 一堆函数"。这一节把它收进一个**类**：
> `data_` / `size_` / `cap_` 变成对象的内部状态，`new` / `delete` 的配对责任从**调用者**转移到**这个类自己**。

### 1. `class` 和 `struct` 只差一件事

| | 默认访问权限 | 其它 |
| --- | --- | --- |
| `struct` | `public` | 完全一样：都能有成员函数、构造、析构、继承 |
| `class` | `private` | 同上 |

```cpp
struct PointS { int x, y; };                  // 外面能直接写 ps.x = 10
class  PointC { int x, y; public: PointC(int x0, int y0) : x(x0), y(y0) {}
                int getX() const { return x; } };   // 外面只能通过函数拿
```

**没有别的区别。** 习惯上：只装数据用 `struct`，有行为、要保护内部状态用 `class`。

### 2. 成员函数后面的 `const` 是什么

```cpp
int size() const { return size_; }      // 承诺：这个函数不会改对象的成员
```

`const` 写在参数表后面，表示"不会修改本对象"。
所以 **`const IntArray&` 只能调用带 `const` 的成员函数** —— 这就是 `operator[]` 要写两个版本的原因。

### 3. 构造函数：对象"出生"时自动调用

```cpp
IntArray() : data_(nullptr), size_(0), cap_(0) {}     // ← 冒号后面叫「初始化列表」
```

- 名字和类同名，**没有返回类型**（连 `void` 都不写）
- **初始化列表 vs 函数体里赋值**：初始化列表是在成员"出生"时就给初值；写进函数体是"先默认初始化、再赋值"。
  `const` 成员和引用成员**只能**用初始化列表
- **不写构造函数**时编译器会给一个默认的 —— 但**成员是不确定的值**（不是 0！）

### 4. 析构函数：对象"死亡"时自动调用

```cpp
~IntArray() { delete[] data_; }     // 名字是 ~类名，没有参数、没有返回类型
```

调用时机（本机 demo 实测输出）：

```
  进入 scopeDemo
      [构造] a
      [构造] b（内层作用域）
  内层作用域里
      [析构] b（内层作用域）      ← 内层作用域一结束就死
  内层作用域结束，但 a 还活着
  离开 scopeDemo（马上会看到 a 的析构）
      [析构] a                    ← 出函数才死
```

**规律：出作用域就死；同一作用域里，构造顺序和析构顺序相反（像栈）。**
"传值"还会多走一次拷贝构造：

```
      [构造] outside
      [拷贝构造] outside（说明这里发生了一次拷贝）   ← 值传递时拷了一份
      函数体里：outside
      [析构] outside                                 ← 形参那份先死
  传值调用结束，outside 还在
```

### 5. 拷贝构造：默认是「浅拷贝」（这一节最重要的坑）

三种情况会调用拷贝构造：`IntArray b = a;`、**传值** `f(a)`、函数返回对象。

**默认的拷贝构造 = 成员逐个拷** —— 对指针成员，拷的是**地址**，不是它指向的内容：

```cpp
IntArray a;  a.push_back(1);
IntArray b = a;        // 浅拷贝：a.data_ 和 b.data_ 指向同一块内存！
                       // 于是 a、b 析构时 → 同一块内存被 delete[] 两次 → double free → 崩
```

真实项目里的规矩叫「**三法则**」：**只要需要自己写析构函数，通常也要写拷贝构造和拷贝赋值**
（或者干脆禁止拷贝：`IntArray(const IntArray&) = delete;`）。

想省事就用标准库 —— `std::vector` 这三件事都替你做对了。

### 6. RAII：这一节的核心思想

> **RAII = Resource Acquisition Is Initialization（资源获取即初始化）**
> 把「**资源的生命周期**」绑在「**对象的生命周期**」上：**构造函数里拿资源，析构函数里还资源。**

好处：不管从哪条路离开作用域 —— 正常结束、`return`、抛异常 —— **析构都会跑**，
于是"忘记释放"这件事被编译器接手了：

```cpp
void earlyReturn(int n) {
    IntArray arr;
    arr.push_back(n);
    if (n > 0) return;        // ← 提前 return，这里没写任何 delete，但析构照样跑
}
```

同一思想在标准库里的样子：

| 资源 | RAII 包装 |
| --- | --- |
| 堆内存 | `std::vector` / `std::string` / `unique_ptr` |
| 文件句柄 | `std::ifstream` / `ofstream` |
| 锁 | `std::lock_guard` |

### 7. `grow` → `IntArray`：对照一下

| | 之前（散着的） | 现在（一个类） |
| --- | --- | --- |
| 数据 | `int* data; int size; int cap;` 三个变量 | 三个 `private` 成员 |
| 扩容 | `grow(data, size, cap, v)` 手动调用 | `arr.push_back(v)` 自己判断 |
| 释放 | 调用者记得 `delete[]` | 析构函数自动做 |
| 出错风险 | 忘了释放、忘了扩容、传错 cap | 用的人不可能忘 |

**扩容三步顺序（写错就是"搬之前把家拆了"）**：

```cpp
int* fresh = new int[newCap];                        // ① 申请新块
for (int i = 0; i < size_; i++) fresh[i] = data_[i]; // ② 老数据搬过去
delete[] data_;                                      // ③ 释放老块（必须在搬完之后）
data_ = fresh;  cap_ = newCap;                       // ④ 接手新块
```

实测的容量轨迹（`push` 5 次）：`cap` = **1 → 2 → 4 → 4 → 8**，只重新分配了 3 次。

### 8. 别踩清单

| 坑 | 后果 | 正确做法 |
| --- | --- | --- |
| `new[]` 配 `delete`（漏方括号） | ASan 报 alloc-dealloc-mismatch | `new[]` 配 `delete[]` |
| 扩容时先 `delete[]` 再搬 | use-after-free，数据全乱 | 申请 → 搬 → 释放 |
| 析构函数忘了释放 | 内存泄漏（ASan 会指出来） | 析构里 `delete[]` |
| `operator[]` 返回 `int` 而不是 `int&` | `arr[1] = 999` 改不进去 | 不带 `const` 的返回引用 |
| 只写一个 `operator[]`（不带 const） | `const IntArray&` 用不了 | 两个都写 |
| `sum(IntArray a)` 按值传 | 拷贝整个对象，可能 double free | `const IntArray&` |
| 不写构造函数就直接用 | 成员是不确定的值 | 初始化列表写清楚 |

### 记忆口诀

> **构造函数管"出生"，析构函数管"死亡"；RAII 就是让这两个函数把资源包起来。**
> **默认拷贝是浅拷贝：指针只拷地址，两个对象一块内存 → double free。**
> **写了析构，就要想想拷贝（三法则）；懒得想，就用 `std::vector`。**

## 二十、拷贝构造 与 三法则（深拷贝）

> 上一节写了 `IntArray`：构造 / 析构 / `push_back` / `operator[]`，但**没写拷贝**。
> 这一节补它 —— 因为**默认的拷贝会要命**。

### 1. 默认拷贝 = 浅拷贝（指针只拷地址）

编译器会自动生成一个拷贝构造函数，做的事是"**成员逐个拷**"。对指针成员来说，拷的是**地址**：

```cpp
class Shallow {
public:
    int* data_;
    Shallow(int n) : data_(new int[n]) {}
    ~Shallow() { delete[] data_; }        // 析构本身没问题
};

Shallow a(3);
Shallow b = a;        // 默认拷贝构造
```

实测（`copy-demo.cpp`）：

```
   a.data_ = 0000014B73B38580
   b.data_ = 0000014B73B38580        ← 两个地址完全相同！两个对象共用同一块内存
```

后果两条：
1. 改 `b` 的内容会**同时改到 `a`**
2. 作用域结束时，`a` 和 `b` 各自 `delete[]` **同一块内存** → **double free**

**这不是理论风险**。用 ASan 跑 `copy-demo-浅拷贝会炸.cpp` 的实测输出：

```
ERROR: AddressSanitizer: attempting double-free on 0x1224941a0030 in thread T0:
    #1 ... in Shallow::~Shallow(void) ...\copy-demo-浅拷贝会炸.cpp:16
    #2 ... in main                     ...\copy-demo-浅拷贝会炸.cpp:27
0x1224941a0030 is located 0 bytes inside of 12-byte region [0x1224941a0030,0x1224941a003c)
```

注意它**直接把析构函数那一行点出来了**。

### 2. 什么时候会调用拷贝构造

| 写法 | 调用的是 |
| --- | --- |
| `Vec b = a;` | **拷贝构造**（b 还不存在，正在被创建） |
| `f(a)`（参数按值传） | **拷贝构造**（形参正在被创建） |
| `return obj;`（按值返回） | 拷贝构造（或移动 / 被省略） |
| `c = a;`（c 已存在） | **拷贝赋值**（`operator=`） |

**`Vec b = a;` 和 `c = a;` 是两个不同的函数**，这一点最容易混。

### 3. 三法则（Rule of Three）

> **只要你需要自己写析构函数，通常也要写拷贝构造和拷贝赋值。**

```cpp
class Vec {
public:
    Vec() : data_(nullptr), size_(0), cap_(0) {}
    ~Vec() { delete[] data_; }                                   // ① 析构

    Vec(const Vec& other) : data_(nullptr), size_(0), cap_(0) {  // ② 拷贝构造（深拷贝）
        reserve(other.size_);                                    //    先初始化成空，再申请
        for (int i = 0; i < other.size_; i++) data_[i] = other.data_[i];
        size_ = other.size_;
    }

    Vec& operator=(const Vec& other) {                           // ③ 拷贝赋值
        if (this == &other) return *this;                        //    自赋值检查！
        reserve(other.size_);
        for (int i = 0; i < other.size_; i++) data_[i] = other.data_[i];
        size_ = other.size_;
        return *this;                                            //    返回 *this
    }
private:
    int* data_; int size_; int cap_;
};
```

实测（改成深拷贝之后）：

```
   a: size=3 地址=0000014B73B38440 内容=7 7 7
      [拷贝构造] 新地址 0000014B73B38490 ← 从 0000014B73B38440 复制内容
   b: size=3 地址=0000014B73B38490 内容=7 7 7
   两个地址**不同** —— 各自一块内存，互不影响
   改了 b[0] = 99 之后：a[0]=7、b[0]=99
```

### 4. 拷贝赋值里那三件事，一件都不能少

```cpp
Vec& operator=(const Vec& other) {
    if (this == &other) return *this;   // ① 自赋值检查
    // ② 释放旧内存 + 申请新的 + 拷内容
    return *this;                       // ③ 返回 *this
}
```

- **① 自赋值检查**：`a = a;` 看起来毫无意义，但真实代码里经常发生（引用/指针绕了一圈、数组里同一个元素）。
  没有它，流程会是"先 `delete[]` 掉自己的内存 → 再从**已经释放的内存**里拷数据" → 崩。
- **② 顺序**：一定是**先申请新的、把内容搬过去，最后才释放旧的**（和 `grow` 一个道理）。
- **③ `return *this`**：返回 `Vec&` 而不是 `Vec`，才能连写 `a = b = c`，也不会白白多一次拷贝。

### 5. 不想写这些怎么办

- **用 `std::vector`**：三法则（以及移动语义）它都写对了，你只管用
- **禁止拷贝**：如果这个类本来就不该被拷贝，明确写出来（比"忘了写"安全得多）

```cpp
Vec(const Vec&) = delete;
Vec& operator=(const Vec&) = delete;
```

- **五法则**：C++11 之后，如果这个类要"搬"而不是"拷"（移动构造 / 移动赋值），一共是五个函数 —— 后面再说

### 6. 一句话总结这一节

> **默认拷贝是浅拷贝：指针只拷地址，两个对象一块内存 → double free。**
> **三法则：写了析构，就要想拷贝构造和拷贝赋值。**
> **拷贝赋值三件事：自赋值检查 → 释放旧内存再申请 → `return *this`。**

### 7. 别踩清单

| 坑 | 后果 | 正确做法 |
| --- | --- | --- |
| 只写析构，不写拷贝 | 默认浅拷贝 → **double free** | 三法则一起写 |
| 拷贝赋值忘了自赋值检查 | `v = v` 崩 | `if (this == &other) return *this;` |
| 拷贝赋值忘了 `return *this` | `a = b = c` 不成立 | 返回 `Vec&`，`return *this;` |
| 返回类型写成 `Vec`（漏 `&`） | 多一次拷贝，连写结果错 | `Vec& operator=` |
| 拷贝构造里没先把成员初始化成空 | `reserve` 里 `delete[]` 乱指针 → 崩 | 初始化列表先写 `data_(nullptr)` 等 |
| 对带指针的类用 `memcpy` | 绕过拷贝构造，指针还是共用 | 别这么干，写拷贝构造 |

## 二十一、移动语义 与 五法则（把所有权交出去，而不是复制）

### 1. 先看问题：拷贝的浪费

A10 的深拷贝解决了 double free，但代价是"每次都真的复制一遍内存"。如果一个 `Buffer` 装 100 万个数，
而它马上就要**被销毁**（临时对象、`return` 出去、`vector` 扩容搬家），这次复制完再删掉就是白干。
移动语义就是回答这个问题：**不复制，直接把资源"偷"过来。**

### 2. 右值引用 `T&&` 是干什么的（一句话）

- `T&` 只能绑**左值**：有名字、能取地址的东西（`a`、`v[0]`）
- `T&&` 只能绑**右值**：临时对象、`std::move(x)` 的结果
- 于是编译器在**重载决议**时就能区分"这个对象后面还要用"和"这个对象马上要死"：
  前者走拷贝（安全），后者走移动（快）。

### 3. 移动构造：偷指针 + 把对方置空

```cpp
Buffer(Buffer&& other) noexcept                    // ① 形参是 T&&
    : data_(other.data_), size_(other.size_)       // ② 初始化列表里"偷"（不是复制）
{
    other.data_ = nullptr;                         // ③ 必须把对方置空！
    other.size_ = 0;
}
```

**③ 是整节的命门**：不置空 → `other` 析构时 `delete[]` 会把刚偷走的那块内存还给系统 →
新对象拿着**悬空指针** → ASan 直接报 `double-free` / `heap-use-after-free`。
移动的本质是**所有权转移**：同一块内存只能有一个负责人。

### 4. 移动赋值：自移动检查 → 释放自己 → 偷 → 置空

```cpp
Buffer& operator=(Buffer&& other) noexcept {
    if (this == &other) return *this;   // ① 自移动检查
    delete[] data_;                     // ② 先把自己旧的资源还掉
    data_ = other.data_;                // ③ 偷
    size_ = other.size_;
    other.data_ = nullptr;              // ④ 把对方置空
    other.size_ = 0;
    return *this;                       // ⑤ 返回 *this（才能连写）
}
```

顺序和 A10 的拷贝赋值同源：**先处理自己（自赋值检查 + 释放旧资源），再去拿新的。**

### 5. 实测（A11 答案版，ASan 开着跑）

```
=== 1) 拷贝构造 ===
   a: size=3 地址=000011A97DBA0170
   b: size=3 地址=000011A97DBA0190   ← 两个地址不同：各有一块内存

=== 2) 移动构造  c = std::move(a) ===
   c: size=3 地址=000011A97DBA0170    ← 就是 a 原来的地址（没有复制）
   被移动后的 a: size=0 地址=0000000000000000   ← a 已经变成空壳

=== 3) 移动赋值  d = std::move(b) ===
   d: size=3 地址=000011A97DBA0190
   被移动后的 b: size=0 地址=0000000000000000

=== 4) 自移动  d = std::move(d) ===
   结果：d.size=3   ← 没被清空、也没崩（自移动检查顶住了）

=== 5) 移进 vector ===
   v[0]: size=4  首元素=9

=== 6) 按值返回（RVO）===
   e: size=2 地址=000011A97DBA01F0

拷贝 1 次，移动 3 次

自检：全部正确 ✅
```

三件事直接读出来：

1. 移动构造后 `c` 的地址 = `a` 原来的地址 → **没有分配新内存、没有复制一个元素**，只是把指针换了个主人。
2. 被移动的对象变成 `size=0 地址=0000000000000000` → "合法但空"的状态，析构它是安全的。
3. `拷贝 1 次` 是第 1 段那次真的深拷贝，其余三次资源转移全是移动。

### 6. `noexcept` 为什么必须写

```cpp
Buffer(Buffer&& other) noexcept;   // 少写这五个字母会怎样？
```

- `std::vector` 扩容时要保证**强异常安全**：搬家搬到一半抛异常，它得能回滚。
- 移动构造声明了 `noexcept` → vector **放心用移动**；没声明就假设它会抛 → **退回拷贝**（安全但慢）。
- 所以漏写 `noexcept` **不报错**，只是 N 次搬家里悄悄多出 N 次深拷贝 —— 白写一个移动构造。
- 记法：`noexcept` 写在参数列表**后面**，不是前面。

### 7. `std::move` 到底是什么（它自己什么都不"移动"）

```cpp
Buffer a(100);
Buffer b = std::move(a);   // 真正干活的是这里的移动构造
```

`std::move(x)` 其实只是一个**类型转换**：把 `x` 变成 `Buffer&&`（右值）。
- 它不碰内存，也不调用任何移动函数；
- 真正搬运的是**接住右值的那个函数**（这里是 `Buffer(Buffer&&)`）；
- 所以如果 `std::move(a)` 没被任何函数接住，`a` 一点事都没有。

记法：**`std::move` 是"允许被搬走"的标签，不是搬运动作本身。**

### 8. RVO：连移动都不发生的情况

```cpp
Buffer makeBuffer(int n, int fill) {
    return Buffer(n, fill);       // 直接构造在调用者给的位置上
}
```

C++17 起这叫**保证的复制省略**（guaranteed copy elision）：`Buffer e = makeBuffer(2, 9);`
里那个临时对象根本不产生，`e` 就在原地被构造 → **0 次拷贝、0 次移动**（上面第 6 段实测就是）。

### 9. 五法则（三法则的升级版）

> **写了析构 / 拷贝构造 / 拷贝赋值中的任何一个，就要一并考虑另外两个 —— 这是三法则。
> C++11 之后再加上移动构造和移动赋值，一共五个。**

| # | 函数 | 签名 | 职责 |
|---|---|---|---|
| ① | 析构 | `~Buffer()` | 释放资源 |
| ② | 拷贝构造 | `Buffer(const Buffer&)` | 深拷贝 |
| ③ | 拷贝赋值 | `Buffer& operator=(const Buffer&)` | 自赋值检查 → 深拷贝 → `return *this` |
| ④ | 移动构造 | `Buffer(Buffer&&) noexcept` | 偷 + 置空对方 |
| ⑤ | 移动赋值 | `Buffer& operator=(Buffer&&) noexcept` | 自移动检查 → 释放自己 → 偷 → 置空对方 → `return *this` |

**只写一半会怎样**：只写移动构造、不写移动赋值 → `b = std::move(a)` 找不到移动赋值，
编译器就去找拷贝赋值（右值能绑到 `const Buffer&`）→ **静默地深拷贝一次**：
不报错、不崩溃，只是"你以为移动了，其实没有"。

### 10. 一句话总结这一节

> **移动 = 把资源的所有权交接出去，而不是复制一份。**
> **偷完必须把对方置空（`other.data_ = nullptr`），否则析构时 double free。**
> **`noexcept` 不写不报错，但 vector 会悄悄退回拷贝。**
> **`std::move` 只是类型转换，真正搬运的是移动构造 / 移动赋值。**

### 11. 别踩清单

| 坑 | 后果 | 正确做法 |
| --- | --- | --- |
| 移动后忘了把对方置空 | double free / heap-use-after-free | 偷完立刻 `other.data_ = nullptr; other.size_ = 0;` |
| 移动函数漏写 `noexcept` | vector 扩容退回拷贝（静默变慢） | `Buffer(Buffer&&) noexcept` |
| 移动赋值忘了自移动检查 | `v = std::move(v)` 先释放了自己 → 崩 | `if (this == &other) return *this;` |
| 移动赋值忘了先释放自己的旧资源 | 内存泄漏 | 先 `delete[] data_;` 再接手 |
| 以为 `std::move` 会移动 | "看着像移动"，实际走拷贝 | 记住它只做类型转换 |
| 对被 `std::move` 过的对象再读 | 读到不确定的值（合法但不可用） | 移动后对方只能赋新值或析构 |
| 只写移动、没写拷贝（或反过来） | 另一半被 `delete` 或静默退回深拷贝 | 五法则一起考虑 |
